# 国际化（i18n）

Aether 的国际化系统通过 locale 文件管理多语言文本，在 AE 模板中以 `@i18n.xxx.yyy` 语法引用，运行时支持动态切换语言。Rust 逻辑层可通过 `sys_tr()` / `sys_tr_with_args()` 直接获取翻译字符串。

## locale 文件结构

每个语言对应一个 TOML 文件，放置在 `src/i18n/` 目录下。文件名即为语言代码。

### 文件命名

| 文件路径 | 语言代码 |
|---|---|
| `src/i18n/zh-CN.toml` | 简体中文 |
| `src/i18n/en.toml` | 英文 |
| `src/i18n/ja.toml` | 日文 |

### 文件格式

以 `zh-CN.toml` 为例：

```toml
[home]
title = "你好"
click_me = "点我"
counter = "计数: {count}"
welcome = "欢迎, {name}!"

[settings]
language = "语言"
theme = "主题"
about = "关于"
```

以 `en.toml` 为例：

```toml
[home]
title = "Hello"
click_me = "Click Me"
counter = "Count: {count}"
welcome = "Welcome, {name}!"

[settings]
language = "Language"
theme = "Theme"
about = "About"
```

### 插值占位符

值中使用 `{name}` 语法定义命名占位符：

```toml
counter = "计数: {count}"        # 单个占位符
welcome = "欢迎, {name}!"        # 单个占位符
info = "{name} 有 {count} 条消息"  # 多个占位符
```

**命名占位符的优势**：
- 语义明确：`{count}` 比 `%d` 可读性强
- 位置无关：翻译后可调换占位符顺序，不影响逻辑
- 行业标准：ICU MessageFormat、Fluent、gettext 均采用命名占位符

> 当前不支持复数/性别选择等 ICU 高级特性。如未来需要，`{name}` 格式不冲突，可扩展。

## aether.toml 配置

在项目配置文件中设置默认语言和回退语言：

```toml
[i18n]
default = "zh-CN"
fallback = "en"
```

| 字段 | 说明 |
|---|---|
| `default` | 应用启动时的默认语言 |
| `fallback` | 当当前语言缺少某个 key 时，回退到此语言查找 |

## AE 模板中的引用

### 基本引用（无参数）

使用 `@i18n.节名.键名` 语法：

```ae
Text(@i18n.home.title size=14)
```

生成 Swift：

```swift
Text(I18nManager.shared.tr("home.title"))
```

### 带插值参数的引用

使用 `@i18n.节名.键名(参数名=值)` 语法传递运行时参数：

```ae
// 字符串字面量参数
Text(@i18n.home.welcome(name="世界"))

// 绑定表达式参数 — 运行时从逻辑层取值
Text(@i18n.home.counter(count={Home.get_count()}))

// 多参数
Text(@i18n.home.info(name={User.get_name()} count={Counter.get_count()}))
```

**参数值来源**：

| 语法 | 说明 | 示例 |
|---|---|---|
| `name="字面量"` | 字符串字面量，运行时直接使用 | `name="世界"` |
| `count={Expr}` | 绑定表达式，运行时从逻辑层取值 | `count={Home.get_count()}` |

生成 Swift：

```swift
// 带参数 — I18nManager 执行 {name} → %@ 替换 + String(format:)
Text(I18nManager.shared.tr("home.counter", args: ["count": "\(homeManager.logic.getCount())"]))
Text(I18nManager.shared.tr("home.info", args: ["name": "\(userManager.logic.getName())", "count": "\(counterManager.logic.getCount())"]))
```

## Rust 逻辑层翻译

除了 AE 模板中的 `@i18n` 引用，Rust 逻辑层也可以直接获取翻译字符串。这在你需要将翻译文本传给 `sys_toast()`、`sys_dialog_show()` 等系统 API 时特别有用。

### sys_tr — 无参数翻译

```rust
let title = crate::sys_tr("home.title");
// → "你好" 或 "Hello"，取决于当前语言
```

### sys_tr_with_args — 带插值翻译

```rust
let msg = crate::sys_tr_with_args("home.counter", {
    let mut args = std::collections::HashMap::new();
    args.insert("count", self.count.to_string());
    args
});
// → "计数: 5" 或 "Count: 5"
```

### 实际使用示例

```rust
pub fn on_click(&mut self) {
    self.count += 1;
    let msg = crate::sys_tr_with_args("home.counter", {
        let mut args = std::collections::HashMap::new();
        args.insert("count", self.count.to_string());
        args
    });
    crate::sys_toast(msg, "info".to_string(), 2.0, "bottom".to_string());
}

pub fn on_delete_click(&mut self) {
    crate::sys_dialog_show(
        crate::sys_tr("home.confirm_delete"),
        crate::sys_tr("home.cannot_undo"),
        "confirm".to_string(),
        crate::sys_tr("home.confirm_delete"),
        crate::sys_tr("home.delete"),
    );
}
```

### 工作原理

`sys_tr` / `sys_tr_with_args` 走 **delegate 模式**，与其他系统 API 一致：

```
Rust sys_tr_with_args("home.counter", args)
  → I18nTrDelegate.tr_with_args(key, args)
    → I18nManager.shared.tr("home.counter", args: ["count": "5"])
      → 查找模板字符串 "计数: {count}"
      → {count} → "5" 替换
      → 返回 "计数: 5"
```

Rust 端不知道当前语言，也无法自己做格式化（语言数据在平台层），所以委托给 Swift 的 I18nManager 执行查找 + 插值替换。

## 运行时语言切换

### 从 Rust 逻辑中切换

```rust
pub fn switch_to_english(&mut self) {
    sys_set_language("en".to_string());
}
```

### 切换流程

```
sys_set_language("en")
    ↓
I18nManager.shared.setLocale("en")
    ↓
所有 @i18n 引用自动更新
    ↓
UI 刷新显示英文
```

### 获取当前语言

```rust
let current = sys_get_language(); // "zh-CN" 或 "en" 等
```

## 回退机制

当查找一个翻译 key 时，系统按以下顺序查找：

1. **当前语言** — 如 `zh-CN.toml` 中的 `home.title`
2. **回退语言** — 如 `en.toml` 中的 `home.title`
3. **key 本身** — 如 `home.title`，作为最终兜底显示

### 示例

假设当前语言为 `ja.toml`，但 `ja.toml` 中缺少 `settings.about`：

```toml
# ja.toml
[settings]
language = "言語"
# 缺少 about
```

```toml
# en.toml（fallback）
[settings]
language = "Language"
about = "About"
```

此时 `@i18n.settings.about` 会回退到 `en.toml` 中的值，显示 "About"。

## 平台格式转换

构建时，`{name}` 占位符会转换为各平台的原生格式：

| 平台 | 转换 | 示例 |
|------|------|------|
| Swift (iOS/macOS) | `{name}` → `%@` | `"计数: %@"` |
| Android | `{name}` → `%s` | `"计数: %s"` |
| Web | 保持 `{name}` 不变 | JS 运行时直接替换 |

Web 平台使用 JS 运行时替换，不需要预转换格式。

## 完整工作流

```
1. 编写 src/i18n/zh-CN.toml 和 src/i18n/en.toml，使用 {name} 语法定义占位符
2. 在 aether.toml 中配置 default 和 fallback
3. AE 模板中使用 @i18n.xxx.yyy 或 @i18n.xxx.yyy(arg=val) 引用文本
4. Rust 逻辑中通过 sys_tr / sys_tr_with_args 获取翻译字符串
5. Rust 逻辑中通过 sys_set_language / sys_get_language 管理语言
6. 构建系统生成 I18nManager 代码，自动处理占位符转换、回退和运行时切换
```
